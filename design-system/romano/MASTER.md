# Romano — Design System (Master)

> **LOGIC:** When building a specific page, first check `design-system/romano/pages/[page-name].md`.
> If that file exists, its rules **override** this Master file.
> If not, strictly follow the rules below.
>
> **This file is the single source of truth for all visual decisions in this repo.**
> Never hardcode a hex value, spacing value, radius, shadow, or duration in a
> component. Every value below exists as a CSS custom property in
> `web/src/styles/_tokens.scss` — use the token.

---

**Project:** Romano — workplace coffee ordering
**Category:** B2B Service / Ordering (single-product, order-for-tomorrow)
**Generated by:** `ui-ux-pro-max` skill (`--design-system --variance 4 --motion 4 --density 5`)
**Palette source:** `colors.csv` → *Bakery/Cafe* (warm brown + cream), replacing the
generator's default "appetizing red" — red reads as *error/alert* in an app whose
core UI is order status chips, so the espresso brown was chosen instead.

**Design Dials:** Variance 4/10 (Balanced / Modern) · Motion 4/10 (Standard) · Density 5/10 (Standard)

---

## 1. Style

- **Style:** Soft UI Evolution — subtle depth, softer-than-flat shadows, clear contrast.
- **Pattern:** Minimal single column. One primary CTA per screen. Generous whitespace.
- **Mode support:** Light ✓ Full · Dark ✓ Full (both must be tested, never inferred).
- **Best for:** modern business tools, ordering flows, admin panels.
- **Performance:** ⚡ Excellent · **Accessibility target:** WCAG AA (AAA on primary text).

### Anti-patterns (never do these)

- ❌ Playful / bubbly design — this is a workplace tool.
- ❌ AI purple/pink gradients.
- ❌ Emoji as structural icons (use inline SVG).
- ❌ Raw hex values inside components.
- ❌ Red as a brand/primary colour (reserved for `cancelled` / destructive only).
- ❌ Neumorphism (double inset/outset shadows) — we use *evolved* soft UI, not the 2020 trend.

## 3. Typography

**Pairing:** *Classic Elegant* — Playfair Display (headings) + Inter (body/UI).
The serif carries the "cafe" warmth in hero + product moments; Inter keeps forms,
tables and the admin console neutral and legible.

```css
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=Playfair+Display:wght@500;600;700&display=swap');
```

| Token | Family | Use |
|-------|--------|-----|
| `--font-display` | `'Playfair Display', Georgia, serif` | Hero H1, product name, empty-state headline |
| `--font-sans` | `'Inter', system-ui, -apple-system, sans-serif` | Everything else |
| `--font-mono` | `ui-monospace, 'SF Mono', Menlo, monospace` | Order codes, prices, counts (tabular) |

### Type scale

| Token | Size | Line height | Weight | Use |
|-------|------|-------------|--------|-----|
| `--fs-display` | 2.75rem / 44px | 1.15 | 600 | Hero (desktop) |
| `--fs-h1` | 2rem / 32px | 1.2 | 600 | Page title |
| `--fs-h2` | 1.5rem / 24px | 1.3 | 600 | Section |
| `--fs-h3` | 1.25rem / 20px | 1.4 | 600 | Card title |
| `--fs-body` | 1rem / 16px | 1.6 | 400 | Body — **never below 16px on mobile** |
| `--fs-sm` | 0.875rem / 14px | 1.5 | 400 | Helper, meta |
| `--fs-xs` | 0.75rem / 12px | 1.4 | 500 | Chips, labels — floor, never smaller |

Mobile: `--fs-display` steps down to 2rem, `--fs-h1` to 1.5rem via clamp().
Prices, cup counts and order numbers use `font-variant-numeric: tabular-nums`.

## 4. Spacing, radius, shadow, motion

### Spacing (4px rhythm, density 5/10)

| Token | Value |
|-------|-------|
| `--space-xs` | 4px |
| `--space-sm` | 8px |
| `--space-md` | 16px |
| `--space-lg` | 24px |
| `--space-xl` | 32px |
| `--space-2xl` | 48px |
| `--space-3xl` | 64px |

Container: `--container-max: 1120px`, gutters `16px` mobile → `24px` ≥768px → `32px` ≥1024px.

### Radius

| Token | Value | Use |
|-------|-------|-----|
| `--radius-sm` | 6px | Chips, badges |
| `--radius-md` | 10px | Inputs, buttons |
| `--radius-lg` | 16px | Cards, panels |
| `--radius-xl` | 24px | Hero / feature cards |
| `--radius-full` | 999px | Pills, avatars, stepper buttons |

### Shadow (soft UI evolution — soft, warm-tinted, never harsh black)

| Token | Value |
|-------|-------|
| `--shadow-sm` | `0 1px 2px rgba(69,39,19,.06)` |
| `--shadow-md` | `0 4px 12px rgba(69,39,19,.08)` |
| `--shadow-lg` | `0 12px 28px rgba(69,39,19,.12)` |
| `--shadow-xl` | `0 24px 48px rgba(69,39,19,.16)` |

Dark mode multiplies opacity ×2 and shifts to pure black.

### Motion

| Token | Value | Use |
|-------|-------|-----|
| `--dur-fast` | 120ms | Press feedback |
| `--dur-base` | 200ms | Hover, colour, chip changes |
| `--dur-slow` | 300ms | Panel/modal enter |
| `--ease-out` | `cubic-bezier(.16,1,.3,1)` | Entering |
| `--ease-in` | `cubic-bezier(.4,0,1,1)` | Exiting (~65% of enter duration) |

Rules: animate `transform`/`opacity` only. One or two elements per view.
List entrance staggers 40ms/item. **All motion is wrapped in
`@media (prefers-reduced-motion: reduce)` → duration `1ms`, no transform.**

### Z-index scale

`0` base · `10` sticky header · `20` dropdown · `40` drawer · `100` modal · `1000` toast.

## 5. Component specs

### Buttons

| Variant | Background | Text | Border | Use |
|---------|-----------|------|--------|-----|
| Primary | `--c-primary` | `--c-on-primary` | none | The one CTA per screen |
| Accent | `--c-accent` | `--c-on-accent` | none | Order confirmation only |
| Secondary | `--c-surface` | `--c-fg` | `1px --c-border-strong` | Cancel, back |
| Ghost | transparent | `--c-primary` | none | Tertiary, in-table actions |
| Danger | `--c-danger` | `#FFFFFF` | none | Cancel order (admin) |

- Height: 44px default, 52px large (mobile primary), 36px small (table row) —
  36px rows still get a ≥44px hit area via padding.
- Radius `--radius-md`, padding `0 --space-lg`, weight 600, `--fs-body`.
- Hover: darken to `--c-primary-hover`, `--dur-base`.
- Active: `--c-primary-active` + `transform: scale(.98)`.
- Focus-visible: `outline: 2px solid --c-ring; outline-offset: 2px` — **never removed**.
- Disabled: `opacity: .45`, `cursor: not-allowed`, real `disabled` attribute.
- Loading: spinner replaces label text, button stays disabled, width preserved
  (no layout shift), `aria-busy="true"`.

### Inputs

- Height 48px (≥44px touch), radius `--radius-md`, `1px solid --c-border-strong`.
- **Visible `<label>` above every field** — placeholder is never the label.
- Helper text persists below the field at `--fs-sm` / `--c-fg-muted`.
- Focus: border `--c-primary` + `0 0 0 3px rgba(146,64,14,.15)`.
- Error: border `--c-danger`, message below the field with a warning icon,
  `role="alert"`, and the first invalid field receives focus on submit.
- Validate **on blur**, not per keystroke.
- Semantic types: `tel` for mobile, `password` with a show/hide toggle,
  correct `autocomplete` on every field.

### Cards

`--c-surface`, `1px solid --c-border`, `--radius-lg`, `--shadow-sm`,
padding `--space-lg`. Interactive cards lift to `--shadow-md` on hover over
`--dur-base` and scale `.99` on press.

### Status chip

Pill (`--radius-full`), `--fs-xs`, weight 600, `4px 10px`, icon + label,
status fg/bg token pair. Icon set per status: clock (pending),
arrow-path (in_progress), check-circle (done), x-circle (cancelled).

### Quantity stepper

`−` / value / `+`. Buttons 44×44 circular, value in `--font-mono` tabular,
min 1, max 20. `−` disabled at min with a helper line, `+` disabled at max
with an explanatory message (never a silent no-op). Full keyboard support:
the value is a real `<input type="number">` with `inputmode="numeric"`.

### Tables (admin)

Sticky header on `--c-surface-2`, 56px rows, hover `--c-primary-tint`,
`aria-sort` on sortable columns. **Below 768px the table becomes a card list** —
never a horizontal scroll.

### Toast

Top-right desktop / top-center mobile, `--radius-md`, `--shadow-lg`,
auto-dismiss 4s, `aria-live="polite"`, never steals focus, manual close button.

### Empty states

Illustration or icon + `--font-display` headline + one sentence of guidance +
one action button. Never a bare "No data".

### Skeletons

Any load over 300ms shows a skeleton matching the final layout's dimensions —
no spinners for page-level loads, no layout shift on resolve.

## 6. Layout & responsive

Breakpoints: **375 / 768 / 1024 / 1440**. Mobile-first, no horizontal scroll,
`min-height: 100dvh` (not `100vh`).

- **Mobile:** single column, sticky bottom CTA bar on the order flow,
  content padded to clear it.
- **≥768px:** two-column forms where fields are logically paired
  (first name / family name).
- **≥1024px:** admin uses a persistent sidebar; customer pages stay single-column
  centred at `--container-max`.

Nav: top app bar with the current route highlighted; icon **and** text label on
every nav item. Admin nav is visually and spatially separated from customer nav.
Sign-out sits apart from primary navigation.

## 7. Accessibility contract (non-negotiable)

- [ ] Body text ≥4.5:1, large text ≥3:1 — in **both** themes.
- [ ] Every interactive element has a visible `:focus-visible` ring.
- [ ] Touch targets ≥44×44px with ≥8px between them.
- [ ] Every icon-only button has an `aria-label`.
- [ ] Headings run h1→h2→h3 with no skipped level.
- [ ] Every form control has a `<label for>`; errors use `role="alert"`.
- [ ] Colour is never the only carrier of meaning (status = colour + icon + text).
- [ ] `prefers-reduced-motion` honoured globally.
- [ ] Skip-to-content link as the first focusable element.
- [ ] Route changes move focus to the main region and update the document title.

---

## 8. Voice & copy

Warm, short, concrete. Sentence case for everything — no ALL CAPS, no exclamation
marks. Errors state the cause *and* the fix
("Mobile number must be 11 digits, e.g. 09121234567").
Dates are always shown as a weekday + date ("Tomorrow · Sun 26 Jul"), never a bare
ISO string.

---

## 9. Implementation contract (Angular)

- Tokens live in `web/src/styles/_tokens.scss`, imported once by `src/styles.scss`.
  Components consume `var(--token)` only.
- Standalone components everywhere; **no NgModules**.
- Signals for component state; `computed()` for derived values.
- `provideRouter()` / `provideHttpClient()` in `app.config.ts`.
- Route-level lazy loading via `loadComponent`.
- Shared primitives (button, input, chip, card, toast, spinner) live in
  `web/src/app/shared/ui/` — build the primitive once, never re-style inline.
- Theme is toggled by `data-theme` on `<html>`, defaulting to
  `prefers-color-scheme` and persisted in `localStorage`.

- [ ] Light **and** dark verified independently.
- [ ] Checked at 375 / 768 / 1024 / 1440 px.
- [ ] Reduced-motion verified.
- [ ] Keyboard-only pass: signup → order → admin transition all reachable.
